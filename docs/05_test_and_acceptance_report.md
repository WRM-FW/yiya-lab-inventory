## 2. 认证与 RBAC 权限安全验收测试

| 测试用例编号 | 验收标准项 | 测试执行与设计验证 | 测试结果 | 证据与实现支撑 |
| :--- | :--- | :--- | :---: | :--- |
| **TC-SEC-01** | **未登录用户访问拦截** | 匿名访客直接访问物资、借还或日志路由，路由守卫强制重定向至 `#login`。数据库端 RLS 策略对未登录用户实行 0 权限拒绝。 | **通过** | `src/js/app.js` 路由守卫拦截；<br>`supabase/..._rls_policies.sql` 强制 `auth.uid()` 校验 |
| **TC-SEC-02** | **待审核用户数据隔离** | 新用户注册后默认状态为 `pending`，登录后被严格阻断在待审核提示页，禁止读取任何物资或工具数据。 | **通过** | `tests/test_rbac_security.js`<br>`fn_is_approved_member()` 仅放行 `status = 'approved'` |
| **TC-SEC-03** | **防自我提权攻击** | 普通成员调用用户更新接口尝试将自己的 `role` 篡改为 `admin`，或修改 `status` 为 `approved`，被数据库触发器与 RLS 双重拦截。 | **通过** | `trg_before_insert_users_profile` 触发器强锁角色；`policy_users_update_self_info` 限制成员更新字段 |
| **TC-SEC-04** | **管理员合规审核流转** | 只有具备 `role = 'admin'` 且 `status = 'approved'` 的管理员方可审核新用户或启停用成员账号。 | **通过** | `fn_audit_user_registration` 严格校验操作人管理员凭证 |
| **TC-SEC-05** | **被拒绝与禁用账号即刻吊销** | 将用户状态置为 `disabled` 或 `rejected`，系统路由立即强制登出，数据库 RLS 立即拒绝对该用户的所有数据读取。 | **通过** | `tests/test_rbac_security.js` 验证禁用后 `canAccessInventory` 返回 false |
| **TC-SEC-06** | **绕过前端直调 API 防护** | 攻击者使用 curl 或 Postman 直接请求 Supabase REST API，所有表均启用了 RLS，绕过前端校验无法窃取或篡改数据。 | **通过** | 所有 8 张表均执行 `ENABLE ROW LEVEL SECURITY` |

## 3. 部署与免费套餐运维验收

| 验收标准项 | 验证内容与结论 | 验收结论 |
| :--- | :--- | :---: |
| **GitHub Pages 适配性** | 纯静态 ESM 架构，根目录直接包含 `index.html`，无需 Node 构建步骤，推送到 GitHub 即可访问。 | **合格** |
| **密钥安全性** | 前端仅使用公开的 Supabase `anon public key`，没有包含任何 `service_role` 密钥或数据库直连密码。 | **合格** |
| **数据库迁移脚本可执行性** | 编写了标准的 3 份迁移 SQL 脚本和种子数据脚本，符合 Supabase CLI 与 Web SQL Editor 语法规范。 | **合格** |
| **数据备份与导出能力** | 前端原生支持一键导出 CSV 审计台账；文档中提供了标准的 `pg_dump` 灾备导出与恢复命令。 | **合格** |
| **零额外付费与配额安全** | 整个系统仅依赖 GitHub 免费仓库、GitHub Pages 免费托管及 Supabase 免费配额，不存在任何隐性计费服务。 | **合格** |
